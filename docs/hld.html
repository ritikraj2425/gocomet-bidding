Design

A two-sided freight procurement platform where buyers publish RFQs and carriers compete through live, time-boxed bidding. The API, auction engine, and database run together in one FastAPI service.

Core guaranteeEach qualifying activity can extend the close time by Y minutes, while the forced close time remains an absolute ceiling.

2. Request and bidding flow

From an RFQ draft to a closed auction

ConfigureAdmin creates RFQ, schedule, forced close and X/Y trigger rule.
PublishDraft activates manually or at its scheduled bid start.
CompeteCarriers submit charge breakdown, transit days and quote validity.
EvaluateRank bids and extend when the selected trigger fires inside X.
ConcludeClose at the current deadline or force-close ceiling; retain the audit log.

REST API and auction engine

FastAPI validates requests and enforces role permissions. Bid submission checks the supplier’s best quote, calculates ranking, applies extension triggers, writes audit records, and publishes live updates.

Runtime and persistence

One APScheduler job checks state every 15 seconds. SQLAlchemy uses SQLite by default; DATABASE_URL can point to another SQLAlchemy-supported database with a matching driver.
